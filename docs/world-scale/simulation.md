# Who owns the intersection?

Run gameplay in a display-independent Bevy plugin. A native headless binary drives it with a 30 Hz fixed schedule. The offline native or WASM application can host the same plugin locally. In a connected session a native server owns the world and clients render interpolated snapshots. Browser frame throttling can pause presentation while the server keeps ticking. Begin with one worker and ordinary HTTP-served assets so tick cost, network cost and content delivery can be measured separately.

## State and tick contract

| Record | Fields that must survive | Lifetime |
| --- | --- | --- |
| World object | Stable ID, type, cell and local pose, velocity if moving, ownership epoch, revision, damage and inventory | Saved independently of Bevy Entity handles, render meshes and visibility |
| NPC | Stable ID, goal, route, route progress at a tick, next scheduled decision, outstanding commitments | Persists during far simulation. A detour or door interaction updates these fields. |
| Accepted interaction | Client/session ID and command sequence, accepted tick, target ID, outcome and resulting revision | Durable retry record. Multiple deliveries can return the original outcome. |
| Client view | Stable ID to local Entity mapping, interpolation samples, predicted local pose and outstanding inputs | Rebuildable at join, streaming transitions and graphics device loss |

At each fixed tick, collect eligible commands, order by tick and a stable tie breaker, check reach and current ownership, promote relevant actors, step physics and NPCs, then publish changes after the durable commit. Commit the command outcome and its state change together. Include previously accepted sequences in the checkpoint or retain a durable deduplication window with a protocol for rejecting expired sequences. An acknowledgment lost after commit must be safe to retry.

For milestone 1, checkpoint at a tick boundary and journal the authoritative changed records for each later committed tick, including autonomous changes. Recovery can load a checkpoint and apply revisions in order without replaying a platform-specific floating-point solver. Reject partial journal tails and test a crash between durable commit and acknowledgment. Periodic snapshots plus last-acknowledged input allow a client to reconcile a predicted push. Interpolate remote transforms on a short buffered timeline. Snap large corrections at the simulation layer and measure the time needed to hide the visual discontinuity. Glenn Fiedler's priority accumulator gives an implementable control for bandwidth-limited state updates. [State Synchronization](https://gafferongames.com/post/state_synchronization/)

## Physics and people

Compare a pinned Bevy-compatible physics integration (evaluate Rapier or Avian against this fork's ECS version first) with the exact same integration and scene using sleep and tiering. Use primitive or convex colliders for dynamic props and a static road collider. Record broad-phase candidates, contact pairs, awake bodies, largest connected island, solver iterations and time. A block stacked with crates stresses a coupled island. A row of separated stacks tests independent sleeping and waking. Waking only the object nearest a camera can leave its support asleep. Propagate wake through constrained or contacting neighbors and instrument the largest wake burst. The Box2D island analysis motivates the topology test, although its published timings concern a different solver. [Simulation Islands](https://box2d.org/posts/2023/10/simulation-islands/)

Run nearby contacts at 30 Hz initially. Test fast carts against thin obstacles, and sweep solver substeps or continuous collision detection if the reference tunnels. Schedule mid-distance NPC decisions at 10 Hz and distant route progression at 2 Hz or at arrival events. Stagger work by stable ID. Render interpolation, skeletal animation and decision frequency each get a separate control. Keep goals, reservations and scheduled arrivals through demotion. Promote on predicted impact, interaction reach, a player query or an active pursuit. Use a larger exit radius and minimum dwell time to prevent churn. Compare to all-near simulation at the same tick rate. For crowd motion, start with a route graph and local steering, then test a blocked crossing that requires a new route. [Reynolds, Steering Behaviors for Autonomous Characters](https://www.red3d.com/cwr/steer/)

## Distribution and recovery experiment

1. Generate two adjacent cells with a crate, pedestrian, crossing and two spawn points. Assign stable IDs in the fixture. Record a command stream keyed by tick. The reference run logs accepted actions, contact onset, detour, settling pose and NPC arrival.
2. Serve matching static content by manifest hash. Start with a WebSocket carrying reliable commands and sequenced snapshots for browser and native clients. Keep only the newest unsent superseding snapshot and bound the send queue. Measure head-of-line stalls under loss before testing datagrams. Reliable spawn/despawn records and periodic complete interest snapshots repair a missed view transition.
3. Give player A a push command and player B an overlapping subscription. Duplicate the request, disconnect A before its acknowledgment, unload both local views, restart the server and rejoin from an empty client cache. Compare command outcomes and sorted durable IDs/revisions exactly. For independent solver runs, compare poses with a declared tolerance, initially 2 cm and 2 degrees after settling. Log the worst discrepancy.
4. Increase clients, awake bodies and NPCs independently until fixed-step p99 exceeds the 33.3 ms tick period or queues grow without bound. Track snapshot bytes per client, age of the last applied server tick, correction distance and missed interactions. A far crowd should add little replication traffic for an observer in an empty shop.
5. For a two-worker trial, give the source an ownership epoch. Freeze migrating state at a tick, transfer state and pending commands, commit the destination epoch in a durable owner directory, then route new commands to the destination. Reject obsolete epochs. Keep an interacting physics island under one owner until contacts separate. Exercise duplicate transfers, destination failure before commit and source failure after commit. Compare the border replay with the one-worker reference and count ownerless ticks, dual writes and transfer stalls.

Interest areas, streamed art cells and worker boundaries can then be sized independently. A listening client may need a siren event from beyond its draw distance. A collision that spans two art cells must still have one authoritative outcome.
