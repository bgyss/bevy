# Delivering and rendering the district

## Content residency

Bake a manifest per content version. Each cell lists bounds, coarse mesh, collision proxy, detail LODs, shared materials/textures, compressed bytes and estimated decoded/uploaded bytes. Store authoritative changes to the world separately. Keep collision available before admitting a player into a cell. A late façade texture should have no effect on whether a player can open its door.

Use Bevy's AssetServer handles to share dependencies. Track a cell through request, decode, ready for activation, upload and resident. Rank by time to arrival with a reserved allowance for gameplay-critical proxies. Give each stage its own byte or time limit. Start with 100 m cells and sweep 1, 2 and 4 MiB of uploads per frame. When the player reverses, increment the request generation, discard stale completions and release handles after the final owner leaves. Measure where an allowance is enforced. Limiting ECS spawns cannot by itself bound work already queued for GPU preparation. Compare eager loading to budgeted activation on identical assets, tracking both the hitch and how long the coarse proxy stays visible. Guerrilla's Decima presentation connects authoring, memory and scheduling in a shipped open world. [Streaming the World of Horizon Zero Dawn](https://www.guerrilla-games.com/read/Streaming-the-World-of-Horizon-Zero-Dawn)

## Capability profiles

| Target | Starting path | Capability experiment |
| --- | --- | --- |
| Browser, WebGL2 | Separate WASM build, stock raster PBR with authored LODs, shared materials, probes, hair cards and bounded texture sizes | Test cold download, peak WASM memory, texture limits and a context restore on integrated and mobile GPUs. |
| Browser, WebGPU | Select the WebGPU build after adapter/device negotiation. Retain a launch path to the WebGL2 build on failure. | Check actual features and limits before enabling GPU preprocessing or timestamp queries. Compare CPU activation and GPU visibility independently. |
| Native client | Same cell manifest, interaction trace and camera. Start with stock PBR at the same internal resolution. | Compare experimental meshlets on dense static façades and Solari on one changing light rig on supported hardware. |
| Headless worker | Shared collision and gameplay assets; exclude visual plugins, grooms, textures and GPU dependencies from the server feature set. | Vary simulation rate, active islands and interest sets independently of graphics. |

Ship WASM and immutable assets over HTTPS with compression, correct WASM MIME type and versioned cache keys. Measure bytes through first control including the engine module. Use a single-thread browser control. Worker or shared-memory variants must account for copy cost, cross-origin isolation requirements for shared memory and time on the main thread. Log missing GPU timers as unavailable. Browser support and usable memory are device measurements.

### Hair is a screen-coverage problem as well as a physics problem

Author one groom with a scalp binding, guide curves, follower assignments and an all-cards version with matching color and silhouette. Drive identical head motion through wind, a shoulder turn and a camera pullback past a crowd. First compare cards to static strand ribbons. Then simulate guides at a fixed step with length constraints and head/shoulder capsule collisions, interpolating follower positions in a client-side pass. This isolates simulation cost from raster overdraw. Start with one close character. Sweep guide count, segments per guide, follower density and number of visible heads one at a time.

Choose LOD by projected coverage and maintain hysteresis across thresholds. Try a clustered strand approximation for medium shots, with width and shading calibrated against a dense reference. Cards with baked motion remain a complete far representation. Budget transparency and shadow passes explicitly. Count simulated guides, emitted segments, overdraw, solver time and GPU time. Capture hairline silhouette, highlight motion, scalp/shoulder penetration and temporal trails. An initial close-up gate is 20% less silhouette-mask error than cards at at most 1.5 ms added p95 GPU time at 720p on the nominated laptop, with no disappearing frames across the transition. TressFX supplies a guide for simulation and authoring. HairLOD supplies a specific hypothesis about representing clusters with thicker fibers and aggregate scattering. Neither source establishes a Bevy browser budget. [TressFX](https://gpuopen.com/tressfx/) · [Real-Time Hair Rendering with Hair and Fiber Level of Detail](https://kuiwuchn.github.io/hairlod.html)

### Where a learned renderer could earn its cost

Keep camera, depth, normals, object IDs, motion vectors, exposure and the interactive state as conventional engine outputs. Capture aligned high-quality reference frames on the same replay. First compare full-resolution raster, reduced internal resolution with simple scaling, and temporal reconstruction at equal output resolution. Reset history on cuts, teleports and streamed proxy swaps. Thin hair, signage, moving hands on doors and newly revealed backgrounds make good failure cases. FSR 2 gives a temporal reconstruction reference and a native implementation to study. Browser integration would be a separate port and measurement. [FidelityFX Super Resolution 2](https://gpuopen.com/fidelityfx-superresolution-2/)

A bounded neural experiment could replace the shading of **one** material in a native reference view, conditioned on engine geometry, viewing direction and lighting. Compare against its ordinary PBR material and an offline reference on held-out routes, camera angles and relighting. Record model download, peak memory, inference time, masked appearance error and highlight stability. NVIDIA's neural appearance work provides a learned material representation to study. A later image synthesis or vendor reconstruction experiment can consume the same frame inputs. Count rendered, reconstructed and generated frames separately, measure input-to-visible latency and reject a mode that invents, removes or obscures a usable door or actor. Keep hit testing, collision, ownership and training labels tied to the authoritative scene. [Real-Time Neural Appearance Models](https://research.nvidia.com/labs/rtr/neural_appearance_models/)
